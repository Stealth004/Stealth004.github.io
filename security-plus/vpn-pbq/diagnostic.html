    Learn mode — define success before reading errors

    An IKE SA, a Child SA, and application data prove different things. Define the requested service and the least-privilege negative test before you interpret the incident.

    Step 1 · Trust boundary

    Trace the baseline path

    Topology shows the intended dependencies, not the answer. Read peer identity, protected-network direction, NAT boundary, and the one approved application flow.

    Topology
    Control planeIKE proposal and peer authentication create the IKE SA.
    Protected policyTraffic selectors and IPsec policy create the Child SA.
    Data planeTransport, route, ACL, and application must still succeed.
    Learn mode — ask one question at each boundary

    Can peers reach each other? Did negotiation agree? Did authentication pass? Was a Child SA installed? Did the protected packet match a route and an allow rule? Did the application answer?

    Step 2 · Evidence

    Read across sources

    Expand any record. The timeline contains normal events, a decisive failure, corroboration, and realistic distractors. Source and severity never indicate correctness.

    8 records

    Fast reading pass

    1. Sort by time.
    2. Name the component.
    3. Translate the result.
    4. Find the last good layer.
    5. Confirm the first failure elsewhere.
    Learn mode — evidence is stronger in pairs

    A protocol result identifies the failed stage; a peer configuration, firewall event, route lookup, or ACL record identifies the exact cause. Do not let a later application timeout replace the earlier decisive event.

    Step 3 · Triage

    Find the first failed dependency

    Six decisions score chronology and evidence quality. Work from earliest decisive event, not the loudest final symptom.

    25 points
    Learn mode — last good before first bad

    If the IKE SA never authenticates, route and ACL evidence cannot be causal. If both SAs are established, return to the data path rather than changing crypto.

    Step 4 · Diagnosis

    Classify, correlate, and rule out

    Separate protocol stage from root cause. Similar symptoms can occur at proposal, authentication, Child-SA, transport, route, or policy layers.

    Learn mode — a status code is not always the exact cause

    AUTHENTICATION_FAILED can represent a shared-secret, identity, issuer, revocation, or certificate-lifetime problem. Corroboration determines the repair.

    Step 5 · Remediation

    Make the smallest safe change

    A technically effective but overbroad or insecure change does not earn full credit. Preserve approved crypto, trust validation, and least privilege.

    15 points
    Learn mode — repair one dependency

    Do not open all traffic, disable certificate checks, add every algorithm, or route all networks. Change the failing control at the narrowest component and peer scope.

    Step 6 · Validation

    Retest in dependency order

    Choose the strongest proof, then run the simulated layered test. It stops at the first unresolved dependency in your selected repair.
