    Learn mode — client-based versus clientless

    A client-based tunnel can provide routed network access. A clientless portal proxies supported applications through a browser and is useful when the scope is deliberately narrow.

    Step 3 · TLS and identity

    Establish gateway trust and MFA

    Certificate validation and user authentication solve different problems. Ten decisions are scored across two categories.

    Identity and MFA

    Learn mode — validate before authenticating

    A user should not send credentials until the gateway name and certificate chain validate. MFA then authenticates the user; it does not make an untrusted TLS endpoint safe.

    Step 4 · Traffic policy

    Configure tunnel, routes, DNS, and egress

    Full and split tunneling are requirement-driven. Seven decisions determine where corporate and ordinary internet traffic travel.

    20 points
    Learn mode — split tunnel is more than a toggle

    A valid split design must identify corporate prefixes, protect internal DNS queries, and define local internet breakout. A full tunnel must send both corporate and internet traffic through organizational controls.

    Step 5 · Authorization

    Apply least-privilege access

    The encrypted session is only a transport. Five decisions control device posture, resources, privilege, and auditability.

    15 points
    Learn mode — tunnel up does not mean data allowed

    Authentication answers “who are you?” Authorization answers “what may you use?” Test the requested application and the deny boundary, not only the VPN status icon.
