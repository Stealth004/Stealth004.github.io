    Gap-targeted briefing

    Use this anchor: network-to-network points to site-to-site IPsec; user-to-application often points to TLS remote access. IKE is the control plane that authenticates and negotiates. ESP is the data plane that protects selected packets. A working tunnel still needs routing and authorization.

    Select the secure architecture

    TLS vs IPsec decision rule

    Think scope first. Site/network-to-site/network favors site-to-site IPsec. A remote individual accessing one web application often favors TLS. IPsec remote access and broader TLS tunnels are possible, so the requirement—not a slogan—controls the decision.

    Phase 1 / Phase 2 translation

    Many products label IKE settings “Phase 1” and IPsec settings “Phase 2.” For IKEv2, the more precise model is an IKE SA plus one or more CHILD_SAs. The familiar labels are shown only to help you transfer across interfaces.

    Post-tunnel least privilege

    A VPN provides a protected path; this rule decides what the connected network is authorized to use.

    Port vs IP protocol checkpoint

    IKE uses UDP 500; NAT traversal uses UDP 4500. Native ESP is IP protocol 50, not TCP or UDP port 50. AH is IP protocol 51, adds no encryption, and is generally incompatible with NAT.

    How to read the failure layer

    No IKE SA points to reachability, UDP 500/4500, peers, authentication, or IKE proposal. IKE up but no CHILD_SA points to traffic selectors or ESP proposal. Both SAs up but application traffic fails points to routing, ACLs, or application reachability.
