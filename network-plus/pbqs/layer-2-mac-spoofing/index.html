acct-ws08 (Gi1/0/14). The gateway MAC 0011.a0b2.dc01 is associated in the exercise evidence with its legitimate connection on Gi1/0/1 and with Gi1/0/14. The acct-ws08 workstation also has its own MAC 02aa.7f19.8d10 on Gi1/0/14.

Attack in progress

On-path attack via MAC spoofing. The attacker impersonates the gateway MAC to try to receive frames intended for the real gateway. As the switch relearns the MAC on different ports, forwarding can become unstable, resulting in slow or dropped sessions.

Mitigation

Port security: limit/pin MACs per access port. Configure an appropriate per-port MAC limit and permitted or sticky secure MAC policy to block the unauthorized gateway MAC on an endpoint port. Investigate the workstation and isolate the affected port. Increasing the MAC table limit does not stop spoofing, a user password reset is unrelated, and disabling the gateway SVI breaks VLAN routing for everyone.

Layer 2 ↔ Layer 3 relationship

A workstation compares the destination IP with its local subnet. For a remote IP, it uses the default gateway's IP as the next hop and resolves the gateway's Layer 2 MAC via ARP. The Ethernet frame then carries the gateway MAC as its destination. The switch forwards based on its MAC address table, which is what this attack attempts to manipulate.

Real-equipment nuance: The screenshot's seven-row table is illustrative evidence. A typical switch maintains one active forwarding entry per MAC/VLAN at a time, so in production you would often investigate MAC address flapping, moving-port logs, or repeated table snapshots rather than expect both entries to coexist in a single conventional CAM table display.

THE REPORT

Accounting users report slow or dropped sessions. After investigation, it is determined that the issues primarily involve traffic leaving the VLAN, including data sent to other departments.
